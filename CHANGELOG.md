### Changed

- **Single-folder layout — `skills/<name>/` is now both the skill directory and the plugin root.** Each directory holds `.claude-plugin/plugin.json` and `SKILL.md` side by side, plus its optional `references/`, `scripts/`, `commands/`, `agents/` and `prompts/`. Marketplace entries point at `"source": "./skills/<name>"`. This removes a 792 KB duplicated tree, a sync script and a manual step from the release process. It works because skills.sh scans `skills/` one level deep while Claude Code resolves the marketplace `source` as the plugin root, where a lone `SKILL.md` (no `skills/` subdirectory, no `skills` manifest field) loads as the plugin's single skill — verified with `claude plugin details`, which lists the root skill alongside every command. The collapse relies on this repo being strictly one-plugin-one-skill.
- **Both channels now publish the whole skill directory.** A verified `npx skills add` install writes `scripts/`, `commands/`, `agents/`, `prompts/` and `.claude-plugin/plugin.json` to disk, not just `SKILL.md` and `references/`. This fixes a real defect: `SKILL.md` documented helper scripts that skills.sh users never received. Consequences — `commands/` and `agents/` are Claude-Code-specific formats that other agents receive as inert files, and because `plugin.json` travels with the skill, Claude Code also auto-detects a skills.sh install under `~/.claude/skills/<name>/` as a local plugin `<name>@skills-dir` with no marketplace step (a marketplace install of the same plugin takes precedence and auto-disables that copy, so there is no double-load).
- **Versioning: the commit SHA is the version.** Plugin manifests no longer declare `version`, so every push reaches installed users. Claude Code caches by version string, so the previous hand-maintained `"version": "1.0.0"` froze every installed user on the first release across 26 commits. Official guidance pairs an explicit version with "published plugins with stable release cycles" and a commit SHA with "plugins under active development"; this repo is the latter, and its content is reference documentation with no API surface to version. `CHANGELOG.md` remains the human-readable record of what changed — it is documentation, not the distribution mechanism.
- `skills/opencode-agent-cc` — `SKILL.md` and `references/opencode-cli.md` now anchor the bundled scripts as `${CLAUDE_PLUGIN_ROOT}/scripts/opencode-task.mjs`. A bare `scripts/…` resolved against the user's working directory rather than the skill, so the documented commands could not be run. Both files also note the fallback for agents where that variable does not exist.
- Documentation rewritten for the new layout: `AGENTS.md`, `README.md`, `plugins.md`, `skills.md`, `plugins-agents.md` and `plugins-list.md`. `plugins-list.md` links now resolve to `./skills/<name>` and gained an *Extra components* column flagging which skills ship Claude-Code-only `commands/`, `agents/` or `scripts/`. The `plugins.md` new-plugin checklist gained the `skills.sh.json` / `plugins-list.md` step that CI now gates.
- `.github/workflows/skill-scan.yml` — path filters drop the deleted `plugins/**` and add `.claude-plugin/marketplace.json` and `skills.sh.json`. The scan target (`--skills skills`) is unchanged.
- Corrected the `skill-scan.yml` entry above: it has been gating on repeatable error-class findings since the workflow was hardened, not report-only.
- **opencode-agent-cc** — `scripts/opencode-task.mjs` now guarantees a **single** managed `opencode serve`, with the state recorded declaratively and inspectable. Previously nothing enforced this and, worse, `stop` was broken in a way that leaked servers: `spawn()` returns the pid of the `opencode` shim, which exits immediately, so the recorded pid was already dead — `stop` killed nothing, printed `Stopped server …`, and deleted the record, leaving a live server that the CLI could never see or stop again. Repeated across invocations that is how a machine ends up with a pile of orphaned servers. Now:
  - `server.json` (generated) records the **real** pid, discovered by asking the OS which process owns the port, so it is correct for a server we started *and* one we adopted.
  - `server.lock` is an atomic (`wx`) mutex held only while starting, so concurrent invocations cannot each spawn a server — the winner starts it and the rest wait. A lock whose holder died is stolen rather than wedging the CLI.
  - The port is **no longer auto-incremented**. Scanning `basePort..basePort+9` spawned a child per attempt and never killed the ones that failed, which is the other way instances multiplied. A healthy server already on the port is adopted instead of duplicated; if the port is held by something else the script reports it and exits rather than starting an instance elsewhere. A process that fails to come up is terminated instead of being left behind.
  - New `server` subcommand: url, port, pid, whether that pid is alive, whether the instance responds, uptime, ownership (started-by-us vs adopted) and lock state; `--json` for machine use.
  - `stop` verifies the process actually died (`SIGTERM`, then escalating) before clearing the record, and exits non-zero if it could not. It only group-kills a server it started — an adopted server may share its process group with the user's shell.
  - An explicit `--port`/`--host` that conflicts with the running server is reported on stderr instead of being silently ignored.
  - Health checks are now bounded (`AbortSignal.timeout`). A port that accepts TCP but never answers HTTP previously hung the request, and every caller waiting on it, indefinitely.
- **opencode-agent-cc** — `scripts/opencode-task.mjs` is now portable across Linux, macOS and Windows: the listener pid is resolved with `ss`/`lsof`/`netstat` per platform (the Windows parser rejects a longer port ending in the same digits and a match in a connection's foreign address), termination uses `taskkill /T` on Windows and signals elsewhere, the `opencode` `.cmd` shim is launched through a shell on Windows (with host/port validated, since they cross a shell there), and state lives under `%LOCALAPPDATA%` on Windows instead of an XDG path.
- **opencode-agent-cc** — `stop` now protects work in flight. It queries the server's session-status map and **refuses** while any session is `busy` or retrying, listing the session ids and titles, because killing the process mid-task loses the output that session was producing (the session survives on disk; the assistant message being generated does not). `--force` overrides it as a last resort. `server` shows the same busy sessions, so the refusal is never a surprise. If the server cannot be asked (no answer in time), `stop` says so and proceeds rather than blocking on an unanswerable question.

- **opencode-agent-cc** — the two helper scripts are now **one** CLI: `scripts/opencode-cc.mjs`. `opencode-info.mjs` and `opencode-task.mjs` had no shared code but answered three of the same questions by different means — the configured default model (`opencode debug config` vs `config.get()`), the available models (`opencode models` vs `provider.list()`) and which opencode processes are alive (`ps` + regex vs `ss`/`lsof`/`netstat`) — so their answers could disagree, which is precisely the discrepancy that produced the original silent-failure bug. The environment report is now the `doctor` subcommand, alongside `run`/`status`/`wait`/`result`/`summary`/`list`/`cancel`/`serve`/`server`/`stop`.
  - The **SDK is loaded lazily**: `doctor` and `help` run without it, which matters because a missing SDK is one of the things `doctor` exists to diagnose. Task subcommands still require it.
  - `doctor` reuses the platform-aware process and server code, so it works on Windows. The old report shelled out to `which` and `ps -eo` unconditionally — neither exists there, so binary detection and the process list were both dead on Windows. It now uses `where`/`tasklist` there, and also reports the managed server from `server.json` and the state dir.
  - `doctor` additionally cross-checks the configured default model against `opencode models` and warns when it is missing — the check neither script could make on its own, and exactly the condition that makes every task silently return nothing.
  - Secret safety is unchanged: the report is still built field-by-field from an allowlist, never serialising raw config subtrees, so provider API keys and MCP auth headers are never emitted.

Every `skills/<name>/SKILL.md` and `references/*.md` path is byte-identical across the migration, so existing links and `git blame` on those paths survive.

- The empty root `.mcp.json` (`{"mcpServers": {}}`). The repository root is not a plugin, so the file was inert.
- A checked-in `.github/scripts/__pycache__/*.pyc`; `__pycache__/` and `*.py[cod]` are now gitignored.

### Fixed
- **opencode-agent-cc** — `scripts/opencode-task.mjs` no longer kills an unrelated process when it fails to start. The start-failure cleanup resolved its victim with `listenerPid(port)`, which in the dominant failure mode returns the *foreign* process that caused the failure — so `opencode-task run --port 3000` would `SIGTERM` a dev server on port 3000. It now snapshots the port owner before spawning and never signals a process it did not start; the pre-existing holder is named in the error instead. The cleanup also verifies and escalates, and no longer claims to have stopped something it did not.
- **opencode-agent-cc** — `scripts/opencode-task.mjs` is usable on Windows again: `npm root -g` is invoked through a shell there, because npm ships as `npm.cmd` (there is no `npm.exe`) and Node's path search only appends `.com`/`.exe`, so the lookup threw `ENOENT` and the globally installed SDK — the only documented install — could never be found, making every subcommand fail with "OpenCode SDK not found".
- **opencode-agent-cc** — the Windows listener-pid parser no longer depends on the English word `LISTENING`. `netstat` localises that column (`NASŁUCHIWANIE`, `ABHÖREN`, …), so pid detection silently found nothing outside English installs. It now keys on the local-address column, which is locale-independent and still rejects a longer port ending in the same digits (`:14198`) and the port appearing as a connection's foreign address.
- **opencode-agent-cc** — closed a lock race and a false timeout in `scripts/opencode-task.mjs`: `openSync(…, "wx")` creates the lock file empty and fills it a moment later, so a concurrent reader saw 0 bytes, judged the lock stale and stole it — two starters; an unreadable lock is now aged by its mtime instead. Separately, the waiter's retry loop counted attempts, so stealing one stale lock consumed an attempt and the next pass reported a timeout that had not occurred; it is now bounded by a deadline.
- **opencode-agent-cc** — `--url`/`OPENCODE_URL` is now honoured by `serve` and `server`. `serve` fell through to starting a *managed* server on a different port when the explicit url did not answer (it now refuses, since it does not own that server), and `server` reported on the managed target rather than the url every other command talks to, including attributing an unrelated local pid to it. `serve` also printed a never-assigned `existing.ours`, so its "managed by this CLI" note was dead code.
- A leaked `server.lock`: `process.exit()` skips `finally`, so a failed start left the lock behind until it aged out. Released via an `exit` hook plus `SIGINT`/`SIGTERM` handlers.

- **opencode-agent-cc** — `scripts/opencode-task.mjs` now validates the effective model before submitting a task, instead of failing silently. An unresolvable model is not reported as an error by `opencode serve`: the session is created, the prompt is accepted, and **no assistant message is ever produced** — so `run --wait` printed `(no text output)` and exited `0`, while `status` reported `RUNNING` and `wait` spun until its 1800 s timeout. Because the skill deliberately never passes `--model` (it respects the user's configured default), a stale `"model"` in `opencode.json` made every task silently return nothing. `assertModelAvailable()` resolves the effective model (`--model`, else `config.get().model`), checks it against the connected providers from `provider.list()`, and on a mismatch exits `1` naming the source (`--model` vs `opencode.json`) plus the available models for that provider — or the connected providers when the provider itself is not connected. It only ever validates, never substitutes a model. Unreadable config, unreachable provider list, an unrecognized response shape, or a provider advertising no models are all treated as "cannot verify" and left to the server, so the guard cannot reject a working setup.
- **opencode-agent-cc** — removed an unused `log` variable in `scripts/opencode-task.mjs` (`startServer()` discards the server's output via `stdio: ["ignore", "ignore", "ignore"]`, so the computed `server.log` path was dead).
- **opencode-agent-cc** skill — removed an invisible `U+FE0F` (emoji variation selector) from the `⚠️` heading in `SKILL.md`, which Snyk Agent Scan flagged as W021 (hidden/invisible Unicode). The heading now uses a plain `⚠`.
